# Coding standards

Use meaningful English names, small cohesive components, separation of concerns and predictable state. Follow [engineering standards](engineering-standards.md). Avoid magic values when a configuration or approved token is appropriate; avoid abstraction without an actual need. Do not disable a failing check to make work appear complete. Use issue-linked TODOs and preserve required licences. Formatter, lint, type-check, test and build commands must be agreed with the application foundation before code is integrated; no stack is assumed in this repository today.
